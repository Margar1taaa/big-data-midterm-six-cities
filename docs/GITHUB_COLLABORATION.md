# GitHub 协作说明

本仓库用于报告修改、PPT 制作、分析复核与代码协作。完整原始数据保存在组内 OneDrive，不进入 GitHub；仓库默认设为 **Private**。

## 仓库中包含什么

- 根目录 README、数据源记录、AI 使用说明和最终报告工作稿；
- `scripts/` 中的数据处理与复现脚本；
- `data/cleaned/`、`data/integrated/` 中可直接分析的中间结果；
- `analysis/` 中 Q1–Q5 的脚本、结果表和图片；
- `docs/` 中缺口记录、研究提纲和血缘图。

不提交 `data/raw/`、ZIP 交接包、缓存、日志、Word/PPT 临时锁文件。缺少 raw 数据时按 `data/raw/README.md` 从组内 OneDrive 恢复。

## 分支和提交

1. `main` 只存放经过确认的稳定版本，不直接进行多人同时修改。
2. 每项任务建立独立分支，例如：
   - `report/姓名-章节`
   - `ppt/姓名-主题`
   - `analysis/姓名-问题编号`
   - `docs/姓名-说明`
3. 提交前先同步 `main`，提交信息写清内容，例如：
   - `docs: 修订 NOAA 数据规模说明`
   - `report: 补充 Q3 局限性讨论`
   - `ppt: 新增研究设计与数据血缘页`
4. 通过 Pull Request 合并；至少由另一名组员检查数字、图表来源和文字结论。

## Word 和 PPT 的特殊规则

`.docx`、`.pptx` 是二进制文件，Git 无法可靠地自动合并同一文件中的两份修改。

- 同一时间只指定一人编辑 `研究报告.docx`；
- 其他组员把修改建议写入对应 Markdown 底稿、Issue 或单独的审阅文档；
- 报告负责人合并建议后提交新版本，并在提交说明中列出修改章节；
- PPT 同样指定一名整合负责人，其他人分别提供文字、图表和讲稿；
- 编辑前先确认没有其他人正在修改，编辑完成后立即提交并通知组员。

## 推荐任务分工

| 任务 | 主要产出 | 建议负责人 |
|---|---|---|
| 报告整合 | `研究报告.docx` | 1 名总负责人 |
| Q1–Q5 复核 | 数字、图表、局限性说明 | 各题原负责人 |
| PPT | 演示文稿与讲稿 | 1 名整合负责人 + 各题供稿 |
| 复现检查 | 环境安装、脚本运行、结果对照 | 1–2 名组员 |
| 提交检查 | 文件命名、目录、AI 说明、链接 | 组长/提交负责人 |

## 合并前检查

- 报告中的数字能够在 CSV/JSON 结果中找到来源；
- 图表注明数据范围、单位和来源；
- 不把缺失值当作 0；
- 不提交个人密钥、账号、Token 或本机绝对路径；
- 不提交 raw 大数据或重复 ZIP；
- Word 目录已更新，图片和表格没有错位；
- `README.md`、`data_sources.md` 和最终报告口径一致。

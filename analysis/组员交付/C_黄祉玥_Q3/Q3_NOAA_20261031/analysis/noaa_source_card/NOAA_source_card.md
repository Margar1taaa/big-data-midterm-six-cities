## 1. 来源与获取方式

数据源为NOAA/NCEI发布的GHCN-Daily。[官方产品页](https://www.ncei.noaa.gov/products/land-based-station/global-historical-climatology-network-daily)、[官方数据目录](https://www.ncei.noaa.gov/pub/data/ghcn/daily/)、[变量和文件格式说明](https://www.ncei.noaa.gov/pub/data/ghcn/daily/readme.txt)、[数据DOI](https://doi.org/10.7289/V5D21VHZ)。官方说明核对日期为本次复核日，不冒充原始采集日期。

初始调查表第1、4部分记录拟经官方HTTPS按站下载，无需注册；CDO API是另一个需要Token的访问方式，见[官方API说明](https://www.ncei.noaa.gov/cdo-web/webservices/v2)。原调查C36是“下载后填写”的待办，现已从包中核实纽约中央公园USW00094728实际数据存在，可将样本获取状态改为已获得。原始下载日期、订单/查询参数、具体导出配置未提供。

## 4. 字段与单位

原始宽表核心列为STATION、NAME、DATE和PRCP/SNOW/SNWD/TMAX/TMIN，部分站另含TAVG；有些文件完全没有某要素列，例如洛杉矶USC00041779没有SNOW，不能补造为0。原始站点目录另提供LATITUDE/LONGITUDE/ELEVATION，融合主表保留如下周字段。

| field | definition | unit |
|---|---|---|
| city | 六城大写英文名，与Tycho连接 | — |
| sunday_date | 周日起始标签，和city组成唯一键 | YYYY-MM-DD |
| week_end | 周六=sunday_date+6天；仅单源周表保留 | YYYY-MM-DD |
| tavg_avg | 站内日平均温度的周均，再跨站平均；缺TAVG以(TMAX+TMIN)/2回退 | °F（官方原生记录样本换算支持；导出配置未附） |
| tmax_avg | 日最高温度的周均，再跨站平均；不是周极大值 | °F（官方原生记录样本换算支持；导出配置未附） |
| tmin_avg | 日最低温度的周均，再跨站平均；不是周极小值 | °F（官方原生记录样本换算支持；导出配置未附） |
| prcp_sum | 先计算各站该周有效观测日的日均降水，再对站点取平均；不是周累计量 | in/day（周内有效日均；官方样本换算支持） |
| snow_sum | 先计算各站该周有效观测日的日均降雪，再对站点取平均；SNOW不是SNWD雪深 | in/day（周内有效日均；官方样本换算支持） |
| n_days | 站周有效日数的跨站平均，保留1位小数；不是城市唯一有效日计数 | 天 |
| n_stations | 该周参与气象汇总的站点数；不等同于每个要素的有效站点数 | 站/周 |

本次将USC00475474站1947-01-01至01-03的TMAX/TMIN/PRCP/SNOW共12个本地值与NOAA官方原生.dly记录比对：按温度°C→°F、降水/雪mm→inch换算并按导出精度舍入，12项均吻合。因此本地英制导出解释获得逐值证据；这仍不是对58文件全部单位配置的逐份认证，原下载订单/units参数尚未提供。 原生.dly格式的温度单位是0.1°C、PRCP是0.1mm、SNOW/SNWD是mm，不能把这些原生缩放再次套到已导出本地CSV。PRCP/SNOW周字段虽名含sum，实际是日均口径，单位按日均解释。若换成公制，应温度用(F−32)×5/9，日均水量乘25.4；本次源卡更新不修改主表数值。

## 5. 日转周与质量复核

① 识别真实文件格式，读表内STATION，不从文件名猜站号。② 各站日期归入当周周日，week_end为其后第6天。③ TAVG缺值用同日(TMAX+TMIN)/2回退；站内对各要素有效日求均值，再跨站平均。④ PRCP/SNOW分别用有效观测日作分母，是周内日均，不是周累计。⑤ n_days为站周有效日计数的跨站均值，保留1位小数；n_stations描述该周参与汇总的站点数。⑥ 缺失NA，观测0保留，各要素有效站数可以不同。
